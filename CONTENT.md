# Editing the site

The site is edited at [app.pagescms.org](https://app.pagescms.org) — no code, no
Git. Everything you save is committed to this repository, a build runs, and the
page updates a minute or so later.

## Setup, once

1. Sign in to Pages CMS with GitHub.
2. Install the Pages CMS GitHub App on `jonasjohansson-archive/rosehallgren.se`.
3. Open the repo in Pages CMS. It reads `.pages.yml` and shows two sections:
   **Projects** and **Intro and contact**.

## Projects

One entry per project.

- **Position** decides the order on the page. Lower numbers come first. To move
  a project up, give it a lower number than the one above it.
- **Images and video** is a list you can drag. The **first image** is the one
  shown with the title, and it becomes the large image on that project's PDF
  page; everything after it becomes the collage on the following page.
- **This is a drawing or plan** — tick it for plans, sections and maps. In the
  PDF those get a soft background and are fitted whole rather than cropped, so
  the linework is never sliced through.
- **YouTube ID** turns an entry into a video instead of an image. It can sit
  anywhere in the list.
- **Text** — leave a blank line between paragraphs. A line containing only
  `---` splits the text onto a second slide, for long descriptions.
- **Web address** is the part after the `#` in a link to the project. Changing
  it breaks any link already shared, so it is usually best left alone.

## Adding a photograph

Upload it through the image field, then tell Jonas — the web-sized versions
(the small, fast copies the site actually serves) are generated by
`./build-images.sh` and are not made automatically yet. Until they exist the
build will refuse to publish and say which image is missing, so a half-finished
upload can never reach the live site.

## The PDF

Cmd+P on the site prints a 36-page 16:9 portfolio, two pages per project. It is
generated from the same content, so it stays in step on its own. Use Chrome —
Safari ignores the page size.

## If something looks wrong

Every save is a commit, so nothing is ever lost and anything can be undone. The
build checks the content before publishing and fails on a missing image, a
duplicate web address, an empty title or position, or a malformed link.

## For developers

```
content/projects/<slug>.md   one file per project
content/settings.json        intro copy, contact links, portrait
.pages.yml                   the CMS schema
src/                         the Eleventy template
.eleventy.js                 everything derivable, derived
scripts/validate-content.js  the pre-publish checks
```

`npm run build` validates, renders `_site/index.html`, and copies it to
`index.html` at the repo root — GitHub Pages serves this repo from the root of
`master` (`build_type: legacy`), and `assets/images` alone is 534MB already in
Git, so artifact deployment would upload half a gigabyte per text edit.
`.github/workflows/build.yml` does the same on push and commits the result.

`index.html` is generated. Do not edit or format it; see `.prettierignore`.

The srcset ladders, `sizes` strings, `width`/`height` attributes, print-JPEG
paths and the `deck-tiles-N` / `deck-rows-M` collage grid are all computed at
build time from the files on disk. `npm run serve` for a live preview.
